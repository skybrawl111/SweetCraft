## 🎂 Назначение и функционал системы

Веб-сервис предназначен для автоматизации приёма индивидуальных заказов на торты и десерты с возможностью онлайн-конструирования параметров изделия (вес, начинка, коржи, декор), а также для контроля суточной загрузки производственного цеха кондитерской.

### 🌟 Особое требование Варианта 1:
1. **Автоматический расчёт итоговой цены торта** по формуле:
   $$\text{Цена} = (\text{Вес} \times \text{Тариф начинки за 1 кг}) + \text{Стоимость коржа} + \sum \text{Надбавки за декор}$$
   Расчёт строго инкапсулирован на сервере Django и обновляется на клиенте через асинхронный `fetch` без перезагрузки страницы.
2. **Контроль суточного лимита цеха:**
   Каждая смена кондитеров имеет лимит мощности (35–45 кг готовой продукции в сутки). При попытке клиента оформить заказ на дату, где суммарный вес уже достиг лимита, система возвращает валидационную ошибку и блокирует дату, защищая цех от предпраздничного срыва сроков.

## 📋 Выполнение 15 общих требований практики

| № | Требование практики | Как реализовано в проекте |
|---|---------------------|---------------------------|
| 1 | **Серверная часть на Django** | Архитектура MVT, вся бизнес-логика расчёта цен и лимитов в `models.py` и `forms.py`. |
| 2 | **БД SQLite / PostgreSQL, ORM** | 10 сущностей, связи 1:M и M:M, обращение к данным исключительно через Django ORM. |
| 3 | **Аутентификация `django.contrib.auth`** | Кастомная модель `CustomUser`, хеширование паролей PBKDF2, вход, регистрация, смена пароля. |
| 4 | **Разграничение прав доступа** | 4 роли (`customer`, `confectioner`, `manager`, `admin`). Защита чужих заказов (403 Forbidden). |
| 5 | **CRUD на сайте (не менее 2 сущностей)** | 1) Заказы тортов (создание, просмотр, отмена); 2) Отзывы клиентов (создание, просмотр, редактирование, удаление). |
| 6 | **Каталог с поиском, фильтрами, пагинацией** | Поиск по тексту `icontains`, 3 фильтра (корж, начинка, цена), сортировка по 3 полям, пагинация по 20 с сохранением GET-параметров. |
| 7 | **Сводные показатели и график** | Панель `/dashboard/`: Count (заказы), Sum (выручка), Avg (средний чек), % выполненных + гистограмма загрузки смен. |
| 8 | **Запрос fetch к JSON-представлению** | Асинхронный калькулятор в конструкторе: вызов `/api/check-date-and-price/` с обновлением цены и статуса смены без перезагрузки. |
| 9 | **Загрузка файлов с валидацией** | Загрузка эскиза оформления клиентом (JPG, PNG, до 5 МБ), превью в карточке заказа и админке. |
| 10 | **Печатная форма и экспорт в CSV** | 1) Печатная технологическая карта кондитера `/orders/<id>/print/`; 2) Выгрузка заказов в CSV `/orders/export-csv/`. |
| 11 | **Email-уведомления** | Функция `send_mail` при регистрации, оформлении заказа и смене статусов цехом (консольный бэкенд). |
| 12 | **`transaction.atomic`** | Создание заказа с фиксацией брони суточного веса в графике цеха внутри блока атомарной транзакции. |
| 13 | **Демонстрационные данные** | Команда `python manage.py seed_data`: 35 заказов, 12 тортов, 10 начинок, 10 коржей, 10 декоров, 14 отзывов. |
| 14 | **Адаптивная вёрстка (360, 768, 1024, 1440 px)** | Чистый адаптивный CSS (Grid, Flexbox, media-queries) без тяжелых сторонних фреймворков. |
| 15 | **Git по дням, .env, DEBUG=False** | История коммитов по дням практики, переменные окружения в `.env`, файл `.env.example`. |

## 🚀 Запуск проекта

### 1. Установка зависимостей
```bash
pip install Django pillow
```

### 2. Применение миграций
```bash
python manage.py migrate
```

### 3. Заполнение базы демонстрационными данными (35+ заказов, торты, начинки)
```bash
python manage.py seed_data
```

### 4. Запуск сервера разработки
```bash
python manage.py runserver
```
Сайт доступен по адресу: **http://127.0.0.1:8000/**
